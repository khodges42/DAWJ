# Provisional compatibility and release policy

The prototype plan refers to a policy document that was not supplied. This file
records implementation choices for review; it does not reconstruct that document.
Original application code uses **GPL-3.0-or-later**, including Cargo metadata and
SPDX headers. The repository carries the complete GPL v3 text in `LICENSE`.

M0 has no third-party Cargo dependencies. `Cargo.lock` records all three workspace
packages. `scripts/audit_dependencies.py` fails if any external dependency enters
the graph until its inventory review is deliberately updated. `cargo deny check`
adds advisory, source and license-expression checks in CI; allowlisted licenses
are a screening policy, not proof of every distribution obligation being met.

Before adding a crate/native library, record its exact version, source, SPDX
license expression, selected alternative, bundled code/assets and notice/source
obligations. Review transitive dependencies and platform-specific code. Favor
GPL-v3-compatible permissive licenses. Do not silently accept proprietary,
source-available-only, GPL-2.0-only, unknown, or conflicting terms. LGPL and other
conditional cases need a documented distribution plan before changing the gate.

Before a public release, include corresponding source and build instructions,
required license texts/notices and a complete dependency inventory. Audit samples,
presets, fonts, icons and demo tracks separately from code. Synthetic impulses in
the M0 demo are generated by the program. Supplied design/schema/example files
have no explicit license grant in the bundle: resolve their redistribution terms
or exclude them from distributable artifacts. No software release is performed by
this task. Recheck the Rust standard library and compiler-runtime notices for the
actual distributed executable. This prototype policy needs owner/legal review
before commercial redistribution.
