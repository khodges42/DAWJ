# Provisional compatibility and release policy

The prototype plan refers to a policy document that was not supplied. This file
records implementation choices for review; it does not reconstruct that document.
Original application code uses **GPL-3.0-or-later**, including Cargo metadata and
SPDX headers. The repository carries the complete GPL v3 text in `LICENSE`.

M2.9 restored the previously truncated LICENSE from GNU's canonical
`https://www.gnu.org/licenses/gpl-3.0.txt`, byte-for-byte (35149 bytes, SHA-256
`3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`).
Git attributes disable newline conversion for this file.

M0 has no third-party Cargo dependencies. `Cargo.lock` records all three workspace
packages. `scripts/audit_dependencies.py` fails if any external dependency enters
the graph until its inventory review is deliberately updated. `cargo deny check`
adds advisory, source and license-expression checks in CI; allowlisted licenses
are a screening policy, not proof of every distribution obligation being met.

Before adding a crate/native library, record its exact version, source, SPDX
license expression, selected alternative, bundled code/assets and notice/source
obligations. Review transitive dependencies and platform-specific code. Favor
GPL-v3-compatible permissive licenses. Do not silently accept proprietary,
source-available-only, GPL-2.0-only, unknown, or conflicting terms. LGPL and other
conditional cases need a documented distribution plan before changing the gate.

Before a public release, include corresponding source and build instructions,
required license texts/notices and a complete dependency inventory. Audit samples,
presets, fonts, icons and demo tracks separately from code. Synthetic impulses in
the M0 demo are generated by the program. Supplied design/schema/example files
have no explicit license grant in the bundle: resolve their redistribution terms
or exclude them from distributable artifacts. No software release is performed by
this task. Recheck the Rust standard library and compiler-runtime notices for the
actual distributed executable. This prototype policy needs owner/legal review
before commercial redistribution.


## M1.1 Windows x64 dependency review

The Windows build now uses CPAL 0.15.3 (Apache-2.0) with default features
and optional ASIO/JACK disabled. `windows-dependencies.json` records exact
versions, registry source, license expressions, selected Apache-2.0 alternatives
and upstream license filenames for all seven external Windows x64 packages.
CPAL uses dasp_sample and Microsoft's windows/windows-core/windows-result,
windows-targets and windows_x86_64_msvc crates. Apache-2.0 is compatible with
GPLv3; retain upstream license texts, copyright and applicable NOTICE files,
mark modifications, and provide GPL corresponding source/build instructions
when distributing. No proprietary driver SDK or ASIO SDK is bundled. The
windows target crate includes upstream Windows import libraries; preserve its
upstream license as well. OS audio services/drivers remain system components.

`scripts/audio_dependencies.py` replaces the M0 zero-dependency gate with an
exact Windows x64 version/source/license inventory check. Cargo.lock also
contains dependencies for other CPAL platforms; those are not part of this
Windows build and require their own inventory and native-library review before
shipping another target. This review does not claim cross-platform release
clearance. Cargo-deny remains an additional release check when installed.

## M3 native GUI dependency review

Eframe/egui 0.31.1 adds a native Glow window to the existing GPL-3.0-or-later
application. Default eframe features are disabled; selected features are
`default_fonts`, `glow`, `x11`, `wayland`. Eframe's source declares Rust 1.81,
within the pinned Rust 1.85.1 toolchain. CPAL remains 0.15.3, without ASIO.
No new sample library, synthesizer or proprietary SDK is included.

`windows-dependencies.json` now records **174** registry packages from locked,
Windows-filtered Cargo metadata, including optional resolved packages that may
not be compiled by Glow. Each row preserves exact version, source, upstream
license expression, selected alternative, repository and packaged license-file
paths. The existing inventory gate still compares exact name/version/source/
license tuples. Slash-separated legacy MIT/Apache expressions select Apache-2.0.
Other selected software licenses are MIT, ISC, Zlib, CC0-1.0, BSL-1.0 and
Unicode-3.0, with AND terms preserved for combined works. These selections are
compatible with GPLv3 distribution subject to retaining their notices. The
Boost Software License was added to the screening allowlist for its transitive
code; no unknown or proprietary software license was accepted.

The [pinned default-font crate](https://github.com/emilk/egui/tree/0.31.1/crates/epaint_default_fonts)
also embeds **unmodified, separately licensed fonts**. Its package expression is
`(MIT OR Apache-2.0) AND OFL-1.1 AND Ubuntu-font-1.0`. Select Apache-2.0 for the
Rust wrapper, retain the fonts' original licenses and names, and distribute all
of `fonts/OFL.txt`, `fonts/UFL.txt`, `fonts/Hack-Regular.txt` and
`fonts/emoji-icon-font-mit-license.txt`, including their copyright notices.
Hack's notice also covers its Bitstream Vera ancestry. Font assets are not
relicensed as GPL application source. Ubuntu's license explicitly permits
bundling/embedding under its conditions, and the OFL permits software bundling:
[Ubuntu font terms](https://ubuntu.com/legal/font-licence),
[OFL software bundling guidance](https://openfontlicense.org/how-to-use-ofl-fonts).
The cargo-deny font exceptions are scoped to `epaint_default_fonts =0.31.1`;
they do not approve those licenses for arbitrary application code. Modifying or
substituting fonts needs a fresh asset/rename review.

Several upstream registry packages do not include standalone license files
despite declaring permissive metadata (including the egui family and the existing
dasp_sample). Empty `license_files` entries record that fact rather than invent
files. Before distribution, collect the declared licenses and notices from the
corresponding exact upstream revision/repository, include source/build information,
and verify all bundled fonts and native import libraries. No release package is
created here. Cargo-deny/advisory checking was not available in this environment;
metadata review and the exact inventory gate are not a vulnerability audit.
Linux native-system dependency licensing/packaging still needs a separate review.
