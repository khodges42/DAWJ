# M1.1 output discovery

`audio-backend` exposes the hardware-independent `OutputDiscovery` trait and
owned capability snapshots. The CPAL 0.15.3 adapter uses the default host
(WASAPI on Windows); optional ASIO/JACK features are disabled. CPAL is pinned
for compatibility with the repository's Rust 1.85.1 toolchain.

Run `cargo run -p audio-backend --example inspect_outputs --locked` to inspect
outputs without opening a stream. Each device has a snapshot-local ordinal,
name, supported configuration rows and default configuration. Names need not
be unique; ordinals are not persistent device identifiers. Refresh discovery
after hardware changes.

Rates are inclusive backend-reported ranges in Hz, channels are per row, and
buffer ranges are in frames. A single rate has equal endpoints. Unknown buffer
limits remain unknown. The default configuration reports buffer capabilities,
not a measured or selected callback size. Never form a cross product of rows.
An empty list, enumeration error, failed name query, failed capability query,
and failed default query are distinct outcomes. Per-device failures do not
discard other device information.

These are driver reports, not proof a stream will open or meet latency goals.
No playback, callbacks, device selection, routing, cue assignment, resampling,
DSP, hot-plug monitoring, or other M1 features are implemented. Channel counts
do not establish physical connector mapping or independent cue support.

Tests use synthetic CPAL configurations and hardware-independent discovery
fixtures; real enumeration is a manual smoke check, not a hardware-dependent
test assertion. Physical Windows 11 interfaces and multichannel routing require
separate validation.

Verified locally on Windows x64 with Rust 1.85.1: formatting, workspace/all-target
check, Clippy with warnings denied, all ten tests, and the exact Windows dependency
inventory gate passed. The example enumerated eight outputs, including one
four-channel endpoint; reported rates were 48 kHz and buffer ranges were
0..=4294967295 frames. Those broad WASAPI reports are preserved verbatim and
must not be interpreted as measured physical buffer limits. No stream was opened.
`cargo deny` was unavailable locally; its advisory/license scan was not run.
