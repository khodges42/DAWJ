# M2.1 Part model and M2.2 resident WAV parts

The `parts` crate is a pure, hardware-independent domain reducer. Identity
(`PartId`, `AssetId`), playback configuration, musical timing policy and runtime
`State` are separate values. A deck owns exactly eight available slots, initially
Stopped; each command addresses one slot. Duplicate content identities may be
used in separate slots; the runtime address is deck plus slot. No audio handles,
file paths, allocations or device APIs are needed by command/advance operations.

## Transition table

`P` is the currently active Part; `N` is the requested Part. Pending deadlines
are explicit BeatTicks in the deck's monotonic domain timeline. The caller
resolves quantization from the timing policy, epoch and M0 timebase; the model
does not read a wall clock or guess a boundary.

| Current state | Start(N,t) | Stop(t) | Replace(N,t) / Retrigger(t) | Cancel |
| --- | --- | --- | --- | --- |
| Stopped | QueuedStart(N,t) | Stopped | Error: no active part | Stopped |
| QueuedStart | Latest requested start replaces pending start | Stopped | Error: no active part | Stopped |
| Playing(P) | Same full Part: no-op; different Part: error | QueuedStop(P,t) | QueuedReplace(P,N,t); retrigger uses P | Playing(P) |
| QueuedStop(P,t0) | Same full Part: cancel stop; different: error | Update stop deadline | Replace pending stop with replacement/retrigger | Playing(P) |
| QueuedReplace(P,N0,t0) | Error; use Cancel or explicit Replace | Supersede replacement with stop | Latest replacement/retrigger wins | Playing(P) |

StopNow always immediately clears active and pending state. All explicit
deadlines, including no-op Start/Stop requests, must be >= the model's current
time. Invalid slot, invalid Part or late command returns an error without changing
state. Processing order is serialized caller order; there is one pending action
per slot. Identical repeated requests are idempotent; changed pending deadlines
are intentional rescheduling. This is not a network retry/deduplication protocol.

`advance(now)` rejects backwards time, applies due actions (inclusive boundary),
and returns a fixed eight-element array of applied actions with the original
deadline. Same-identity replacement reports retrigger=true so restarting a source
is observable even if the resulting Playing value is unchanged. A subsequent
advance emits no duplicate effect. Call advance before accepting commands at a
boundary to establish a consistent tie order. Commands queued for the current
tick apply on the next explicit advance, not implicitly during command acceptance.
Late advances retain the original action timestamp; they do not prove that audio
was rendered on that frame.

Synchronous `complete(slot)` marks one-shot EOF: Playing/QueuedStop become
Stopped; QueuedReplace becomes QueuedStart retaining the future new Part. Other
states reject completion. This method belongs to the reducer's serialized owner,
not an asynchronous acknowledgement channel; later cross-thread commands will
need instance/command identities and a bounded ordered scheduler bridge.

Nominal part length is positive musical metadata. It neither stops a playing
source nor wraps the deck phrase. Phrase position is `(now - epoch) mod phrase`,
computed independently with wide integer arithmetic. A Part's quantum is positive
policy metadata; nominal duration does not imply sample duration, BPM matching,
time stretching or a reset of the phrase epoch.

## Sample preparation and playback

`audio_backend::samples` loads local RIFF/WAVE assets before stream construction.
Supported formats: mono/stereo PCM signed 16/24/32-bit and IEEE float32. Unknown
chunks and word padding are handled; duplicate fmt/data chunks, invalid RIFF
lengths, inconsistent alignment/byte rate, empty/truncated data, unsupported
formats (including WAVE_FORMAT_EXTENSIBLE/compressed/RF64), NaN/Inf and out-of-range
float samples are rejected. Missing files return errors. Input reads are capped
at 64 MiB, with a one-byte oversize sentinel; decoded PCM is capped at 128 MiB.
The eight-slot deck's combined canonical PCM is also capped at 128 MiB. Preparation
may temporarily hold the encoded input and decoded PCM together; callers should
load sequentially and respect their control-thread memory budget.

Rate policy: exact equality with the requested stream rate is required. There
is no runtime or automatic resampling, pitch shifting or time stretching. Prepare
assets at the selected rate offline. Mono expands to duplicate L/R during decode;
stereo order/polarity is preserved. Immutable canonical stereo storage is owned
by the prepared voice until stream destruction. The rate and asset ID must match
the Part and engine configuration; no filename-derived identity is inferred.

One-shot starts at frame zero and emits each frame once; at exclusive EOF it
emits zero without advancing its cursor. Loops use explicit half-open source-frame
bounds `[start,end)`, start directly at start (no intro), and wrap from end-1 to
start. Position reports the next source frame in asset coordinates; elapsed frames
are a separate saturating consumed-frame count. Loop bounds are canonical sample
frames at the required rate, not BeatTicks. Rendering has no block-size limit,
file I/O, decoding, allocation, locks or source ownership changes.

Boundary policy is explicit. `Preserve` leaves authored samples untouched and
requires suitably continuous assets. `Fade { frames }` prepares symmetric linear
edge fades on the one-shot region or chosen loop region, limited to half its
length. Both endpoints become zero when fade length > 0. No overlap or time
compression occurs: the loop period remains exactly end-start, with a short
level dip at the seam. Regions shorter than four frames preserve their transients;
they cannot simultaneously preserve their entire waveform and guarantee a smooth
endpoint. Very short loops or Preserve may intentionally contain discontinuities.

Prepared sample sources bypass the mixer's legacy unconditional source-boundary
fade, resolving the review's erased short-onset finding for this new path. Bus
gain/crossfader ramps and independent master/cue peak protection remain enabled.
Legacy Tone/Buffer behavior is retained. End-of-stream or emergency stop is still
subject to the M1 lifecycle limits; the demo fades the bus before pausing.

`SampleDeck::prepare` adapts a domain Playing/Stopped snapshot into up to eight
resident voices. Playing slots require a matching asset; stopped slots require
none. Queued states are rejected rather than silently treated as applied. This
is an initial snapshot adapter, not an implementation of live quantized command
delivery or asset swapping. `PlaybackSource::Parts` integrates it into either
existing deck bus and preserves the master/cue routing API. `PlaybackSource::Sample`
also supports a single prepared voice. Eight-slot summing uses a fixed 1/8 gain
per voice to bound full-scale addition. Runtime playback does not mutate the
separate domain model: the owning integration must report completion explicitly.

## Demo and validation

```
cargo run -p audio-backend --example sample_parts --locked --offline -- --fixture target/m2-fixture.wav
cargo run -p audio-backend --example sample_parts --locked --offline -- --render target/m2-fixture.wav target/m2-render.wav
cargo run -p audio-backend --example sample_parts --locked --offline -- --check target/m2-fixture.wav
# Explicit audio opt-in, three-second countdown, four seconds playback:
cargo run -p audio-backend --example sample_parts --locked --offline -- --play target/m2-fixture.wav
python scripts/validate_m1.py
```

The generated mono fixture is synthetic cleared test material, deliberately very
quiet. The render demo produced 96000 stereo PCM16 frames at 48000 Hz, with nonzero
output (peak 3 PCM16 counts). The sample-backed paused stream built successfully
on Speakers (HyperX Cloud III S Wireless), stereo 48000 Hz f32, default buffer
request. No audible playback was started for this task. The opt-in demo is
available; acoustic correctness, new long-soak performance and physical cue
isolation were not newly verified.

Tests cover domain transitions, repeated/conflicting commands, cancellation,
retriggers/applied actions, EOF, eight slots and independent phrase position;
WAV formats, malformed/truncated/missing assets, mono/stereo, loop bounds, exact
positions, prepared fades and short onsets; eight sample voices and exact output
across variable callback partitions. All existing M0/M1 tests remain part of the
workspace gate. Final validation passed all 44 tests, fmt, workspace check,
Clippy with warnings denied, doc-tests and the dependency inventory gate.
No external dependency was added: decoding uses the standard
library and the new `parts` workspace crate is GPL-3.0-or-later. The Windows
seven-package dependency inventory is unchanged. The truncated root license
identified by the review remains a separate distribution blocker until restored.
